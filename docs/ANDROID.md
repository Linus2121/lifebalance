## Windows setup
Install Node.js 22+ and Android Studio 2025.2.1+ with Android SDK Platform 36 and the bundled Java runtime. From the repository root:

```powershell
npm ci
npm run android:sync
npm run android:open
```

In Android Studio let Gradle sync finish, connect an Android phone with USB debugging enabled, select it and press Run. Repeat `npm run android:sync` after web changes. The mobile build copies only approved client assets into ignored `www/`; never point Capacitor at a remote server URL. The native app does not register the web service worker. Signing keys and local SDK settings are ignored by git.

## Data and release limitations
Browser storage and native WebView storage are separate. Existing browser data is not erased or automatically transferred. Export a browser backup before testing; native file export/import and migration still require implementation/device verification. Native scheduling and migration implementation are described below. Android Back behavior, external link handling, account sync and secure credential storage remain later work. Notification permission is requested only when Enable native reminders is pressed. Closed-app delivery is not yet device-verified.

Android cloud backup is disabled for this initial shell because it may contain sensitive local records. This is not a replacement for encrypted storage or an export/import backup flow.

## Step 2 implementation update — 2026-10-29
Native adapter now uses Capacitor Local Notifications for appointment, workout, meal and hydration schedules generated by the existing reminder engine (including multiple offsets). It reconciles pending alarms after saves/imports and when the app resumes; removed/edited alarms are cancelled and new ones scheduled. Snooze actions open the app and schedule a 10-minute or 1-hour delay. Notification details stay generic unless the user enables details. A private notification channel hides lock-screen contents by default (users can change Android channel settings).

The Settings page in native builds shows native scheduling state instead of requiring a web server. A 15-second test alarm is provided. Scheduling success is not represented as proof of real delivery. The plugin restores scheduled alarms after reboot; that path remains untested on devices. Time-zone changes are reconciled on resume; alarms already queued are absolute instants until then. The horizon remains 45 days / 300 reminders; users must reopen the app to replenish it. No exact-alarm permission is requested in this phase; inexact delivery may be delayed by Android, idle modes and manufacturer restrictions. Force-stop can prevent notifications until the app is opened again.

Native exports now use a cache file and the Android share sheet; users choose a destination. JSON imports use the existing native file chooser, validation, record-count confirmation and pre-import restore copy. Native import/export and destination file access still need phone testing. Temporary exports contain private records and remain in the app-private cache until cleared by Android; they are not durable backups. The browser's existing data stays in the browser.

`.github/workflows/android.yml` provides an unsigned-for-release debug APK build with Java 21 and SDK 36 on GitHub Actions. This workflow has no production signing keys. It must successfully run before an installable APK is claimed. Native compilation was not possible in this workspace because SDK download approval was blocked. Android Studio has not been installed on the user's laptop. Existing source-level tests plus four native scheduling tests pass (45 total).

Still pending: phone tests (foreground/background/closed/reboot/DST/permissions/snooze/accessibility/migration), store signing, full secure credential storage and account configuration, pricing and store submission. Native scheduling is not a medical or emergency alarm service.

## Alert tone selection — 2026-10-29
Android Settings now includes Alert tone / Choose alert tone, opening the existing LifeBalance reminders notification category's sound controls. Android owns the persistent choice; returning to the app refreshes the displayed tone name. Silent is shown when the category has no sound or its importance suppresses sound. The same category is used for reminders, snoozes and the test notification. No storage/audio permission or extra tracking is added. Do Not Disturb, app permission and notification volume can still prevent sound. Android 7 falls back to app notification settings; category-specific tone selection requires Android 8+. Version 1.0.1 (code 2). Samsung UI behavior and audible delivery require device testing.
