# Work — version 1.1.0 · last updated 2026-10-30

## Implemented
The Work tab has Overview, Schedule (agenda/calendar), Days off, Breaks and Meetings. Shifts, breaks and staff meetings are regular shared events marked with a work type, so existing date/time-zone recurrence, edit-one/edit-series, cancellation, calendar export and reminders are reused. Overnight shifts end the next day. Separate weekly shifts can represent different working weekdays; repeats support daily, weekly, fortnightly and monthly patterns. Meeting notes hold agenda/preparation details and optional participant names; no invitations are sent. Valid http/https meeting links can be opened. Work today appears on Today; all work commitments also appear in Events.

Creation shows a confirmation with actual next reminder dates/times, skipped past alerts and near-term conflicts. At event time is selected initially. Break-end alerts are optional and use the same notification privacy and sound preferences. Edits/deletions cancel or rebuild schedules through the existing reminder pipeline. Conflict checks are advisory over the next 35 days; they do not enforce employment rules. Break-inside-shift checks support overnight shifts.

Annual leave asks for a year and total allowance, then books a day/date range. Total / Used-booked / Remaining includes future bookings immediately, with no approval workflow. Planned shift start dates are counted when a shift roster exists; otherwise selected working weekdays (initially Mon–Fri) are used. A blank deduction computes automatically. A correction allocates to the earliest working dates, then other dates in the range if needed; half days are accepted. Review the allocated dates before saving. Each date is deducted at most once across overlapping bookings (largest daily allocation, capped at one). Edits/deletions recalculate the union. Cross-year ranges debit each year's own allowance. Allowance overruns are warned, not blocked. Existing allocations are snapshots, so editing working days does not retroactively change past bookings.

## Storage, migration and sync
Data schema 3 adds `work.workingDays`, allowance entries keyed by year and leave bookings with per-date allocations. Events retain all existing fields plus workKind/endReminder. Schema 1/2 records upgrade in place under the existing storage key; old personal records remain. When possible, a pre-upgrade snapshot is saved locally and can be exported from Settings. Work records and balances round-trip through validated JSON backup/import. Older app versions reject schema-3 backup imports; update every device before syncing. The updated server rejects lower-schema writes replacing higher-schema data; redeploy it before allowing older clients to connect. The shared merge engine merges leave/allowances by ID and exposes conflicting changes through the existing conflict review.

Account/backend hosting is still not configured by this release. No live cross-device sync, account credential hardening or backend deployment is claimed. Browser and packaged app storage are separate: use backup/import to transfer data. Keep backups private. Installation/signature conflicts must not be resolved by uninstalling before exporting data.
